# 第三阶段 SOP：核心页面策划与 Blog 模板

对应 AgentGuard 周期：2026-07-22 至 2026-07-28

## 这周要解决什么

第二阶段已经回答“市场里有哪些页面和关键词”，这一阶段要把数据变成客户能执行的网站方案。

这周结束时，每个准备建设或修改的核心页面都应该有明确的路径、主关键词、页面任务、模块顺序和可审核文案。经常重复生产的 Blog 页面还要先定好共用模板，避免每写一篇就重新发明结构。

AgentGuard 这轮最终形成了 28 个核心页面策划。28 是 AgentGuard 当时的范围，不是以后所有客户的固定数量。

## 开始前要准备什么

- 第一阶段的现有页面清单、技术问题和产品事实表。
- 第二阶段的关键词总表、关键词与页面对应表、竞品页面母库、URL Map 初稿和页面优先级。
- 客户已经确认的产品定位、栏目名称和主要转化动作。
- 设计、开发或 CMS 侧对页面结构的基本限制。

## 一步步怎么做

### 第一步：确定这批要做哪些页面

先按业务价值、搜索需求、现有页面问题和制作依赖选择一批页面，不要把母库里的所有候选都直接立项。

每个页面先标明：

- 这是修改现有页面，还是新建页面。
- 页面属于 Homepage、Feature、Solution、Pricing、Docs、Guide、Best、Review、Compare、Glossary 等哪一类。
- 它主要帮助用户完成什么任务。
- 它承接哪个主词和哪些辅助词。
- 它应该放在哪个栏目和 URL 下。

### 第二步：为每页选择同类型参考页面

从第二阶段的竞品页面母库中，选和当前页面类型相同、搜索任务相近的页面。产品页看产品页，Compare 看 Compare，Glossary 看 Glossary。

如果母库里的页面已经过时或正文不完整，再补查当前搜索结果和公开页面。不要拿一篇流量很高的 Guide 去决定产品页结构。

### 第三步：拆解竞品页面为什么这样排

对选中的页面记录：

- Title 和 H1 如何表达主题。
- 首屏先讲用户问题、产品能力还是证据。
- H2/H3 按什么顺序推进。
- 表格、FAQ、截图、流程图放在哪里，解决什么阅读问题。
- CTA 出现几次，分别让用户做什么。
- 哪些信息竞品普遍都有，哪些重要问题没人讲清。

只学习组织方式和表达机制，不复制原句、标题顺序、图片、客户 Logo、数字或产品承诺。

### 第四步：先写页面信息架构

每个页面先写清：

- 页面目标和目标读者。
- 主关键词和辅助关键词。
- 现有页面需要保留、删除、合并或改写的部分。
- 最终模块顺序。
- 每个模块要回答的问题、需要的证据和 CTA。
- 内部链接应该去哪里。
- 还缺哪些客户确认或设计资产。

页面信息架构通过后，再写完整文案。这样客户改结构时，不必把整篇文案推翻。

### 第五步：只用客户事实填页面文案

竞品负责告诉我们“这一类页面通常怎样组织”，客户自己的公开资料负责回答“页面里可以写什么”。

页面文案至少包含：

- Meta Title、Meta Description、Canonical path。
- H1 和首屏说明。
- 按已确认结构写出的正文模块。
- FAQ、CTA、内链和图片文字建议。
- 页面状态和上线前待确认项。

没有一手证据的产品能力、价格、客户数量、认证和效果数字保留为空或待确认，不能从竞品页面借过来。

### 第六步：把重复页面整理成模板

对 Guide、Best、Review、Compare、Glossary 等会持续生产的页面类型，整理共用结构：

- 每类页面的读者任务和基本模块。
- 需要哪些关键词、竞品和产品证据。
- Meta、正文、FAQ、CTA、内链、图片和结构化数据怎么安排。
- 哪些页面类型风险更高，需要额外证据或审核。

模板是空白框架。具体标题、章节数量、CTA 次数和图片形式仍要按当前关键词和同类型竞品重新判断。

### 第七步：交给原型、PRD 和设计

把页面信息架构、最终文案和模板交给页面需求、原型和设计规范。页面设计人员不应该再去猜哪个模块必须保留、哪段是产品事实、哪个 CTA 还没确认。

## 这周会得到哪些产出

| 产出 | 里面要有什么 | 后面拿来做什么 |
|-|-|-|
| 关键词与页面对应稿 | 每页主词、辅助词、意图、路径和状态 | 页面文案、内链和后续效果跟踪 |
| 页面信息架构 | 每页目标、参考依据、模块顺序、内容要求、修改原因 | 原型、PRD、设计和开发 |
| 核心页面文案 | Meta、H1、正文、FAQ、CTA、内链和待确认项 | 客户审核、CMS Draft、网页实现 |
| Blog 页面模板 | Guide、Best、Review、Compare、Glossary 等共用结构 | 第四阶段单篇 Brief 和批量生产 |
| 页面需求与原型说明 | 页面模块、交互、图片和移动端要求 | 设计和开发排期 |
| 上线阻塞清单 | 缺失事实、未确认路径、链接、素材和负责人 | 发布前 QA |

## 同一批资料还能支持什么

- 页面信息架构可以直接变成 PRD 和原型内容，不需要设计人员重新研究 SEO。
- 关键词与页面对应稿会成为后续内链计划和内容更新的依据。
- Blog 模板会进入单篇 Brief，减少重复讨论 Metadata、FAQ、CTA 和结构化数据。
- 竞品页面拆解会在第四阶段继续使用，但写具体文章时必须补查当前同类型搜索结果。

## 以后照 AgentGuard 哪份格式交付

这一阶段默认使用 AgentGuard 的三份客户审核稿：

1. `review-pack/task1-p0-client-deliverables/01-keyword-intent-mapping.md`
2. `review-pack/task1-p0-client-deliverables/02-page-information-architecture.md`
3. `review-pack/task1-p0-client-deliverables/03-english-seo-page-copy.md`

三份文档的顺序不能反：先确认关键词和页面，再确认结构，最后审核完整文案。

Blog 共用部分参考飞书中的“博客页面 SEO 模板规划”“博客页面模块需求”和“Schema JSON-LD”。新客户复制这些文档的栏目和审核顺序，里面的 AgentGuard 路径、产品事实和页面数量全部换成新客户的真实资料。

## 什么情况下不能进入下一阶段

- 一个页面同时有多个互相冲突的主搜索意图。
- 页面路径、栏目或页面类型还没确认。
- 页面结构来自不同类型的竞品页面，拼在一起却没有清楚的读者任务。
- 完整文案已经写好，但产品事实没有来源。
- 新页面与现有页面抢同一个主词，仍没有保留、合并或改道决定。
- Blog 模板被当成固定文章大纲，准备原样套到所有主题。
