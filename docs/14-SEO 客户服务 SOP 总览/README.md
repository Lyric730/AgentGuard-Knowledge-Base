## 一轮完整收集，大致按下面的顺序走：

```text
了解客户产品和当前网站
→ 全网筛选约 10 个有参考价值的竞品
→ 用 DataForSEO 拉每个竞品排名靠前的 100/200 个页面
→ 再查这些页面排名靠前的 Top 50 关键词
→ 清洗、去重、判断搜索意图和页面类型
→ 得到“竞品页面母库”和“关键词母库”
→ 继续产出网站架构、页面规划、内容计划、Brief 和正文
```

这里的约 10 个竞品、100/200 个页面、Top 50 关键词，是 AgentGuard 这次跑通后的默认起点。新客户的网站规模、行业宽窄和预算不同，数量可以调整。但不能省掉“竞品页面”和“这些页面实际排名的关键词”这两层数据。

## 一份源头资料，后面怎么反复使用

| 收集到的资料 | 先产出什么 | 后面还能继续做什么 |
|-|-|-|
| 客户现有网站、产品资料、公开文档 | 站点基线、技术 SEO 报告、产品事实表 | 判断哪些页面保留或修改；限制正文里能写什么、不能写什么 |
| 权威竞品名单 | 竞品池、产品竞品报告 | 决定要长期跟踪谁；为 Compare、Review、Best 类内容准备候选对象 |
| 竞品排名靠前的页面 | 竞品页面母库 | 看竞品靠哪些页面拿流量；拆页面类型、目录、标题和页面结构 |
| 每个竞品页面的 Top 50 关键词 | 关键词母库 | 做关键词总表、搜索意图、主题聚类、主词与辅助词、页面优先级 |
| 关键词母库 + 竞品页面母库 | URL Map、网站架构、内容规划 | 决定一个词应该给哪个页面，避免多个页面抢同一个词 |
| 某个主题的当前 Google 结果 | 单篇 Article Brief | 重新确认这一篇现在面对哪些页面，不能只依赖几周前的母库 |
| 同类型竞品正文 | 标题、开头、章节、表格、CTA、视觉拆解 | 指导 Brief 和正文写法，但不复制竞品原文和章节顺序 |
| 客户一手产品证据 | 页面文案、Blog 正文、FAQ、CTA | 核对产品能力、限制、链接和表述，避免写出没有证据的承诺 |
| 审核意见和返工记录 | 生产规则、QA 清单、Brief 模板 | 下一批直接复用已经修正过的格式，减少重复返工 |

真正需要保留的不是某一张表，而是这条关系：每份交付物都要能说清它用了哪些上游资料，也要说清它会交给哪些下游工作继续使用。

## 五个执行阶段

| 阶段 | 这阶段要回答的问题 | 主要产出 | 下一阶段拿什么走 |
|-|-|-|-|
| 第一阶段：站点摸底 | 客户现在有什么，网站有什么问题，哪些事实可以公开写 | 技术 SEO 报告、现有页面清单、产品事实表、权限缺口 | 最终域名、现有页面状态、可写产品事实、先修问题 |
| 第二阶段：数据母库 | 谁是真正值得参考的竞品，它们靠哪些页面和关键词获得搜索流量 | 竞品池、竞品页面母库、关键词总表、关键词与页面对应表、内容集群 | 经过清洗的页面、关键词、意图、优先级和来源 |
| 第三阶段：页面策划 | 客户应该做哪些页面，每页按什么结构表达 | 页面架构、关键词分配、核心页面文案、Blog 模板、页面需求 | 已确认的页面路径、主词、结构、写作和设计要求 |
| 第四阶段：内容生产 | 一篇具体内容怎样从数据走到可审核成稿 | 单篇 Brief、正文、图片、QA 记录、飞书审核稿 | 已回读的审核稿和剩余上线条件 |
| 第五阶段：滚动规划 | 下一批先做什么，前一批经验怎样变成固定做法 | 内容候选池、优先级、下一批 Brief、流程修订 | 一组可直接进入生产的选题和已更新模板 |

## 每个阶段都要留下的东西

以后服务新客户，每个阶段至少留下四类内容：

1. 给客户看的主文档：结论、建议、待确认项都在一份文档里，不让客户去翻内部文件。
2. 执行用的表：保存页面、关键词、优先级、负责人和状态，方便继续生产。
3. 来源记录：写清数据来自哪个竞品、哪个页面、哪个市场、哪一天。页面抓不到或数据缺失，也要如实写。
4. 交接说明：告诉下一阶段应该读取哪些文件，哪些结论已确认，哪些事情还不能做。

文件很多时，内部可以保留原始数据和检查记录；对客户只保留一份主报告或一张主表。AgentGuard 的技术 SEO 审计已经采用了这种做法。

## 给 Skill 和 Agent 的要求

这里不需要重新建设一套复杂系统。以后检查或调整现有 Skill 时，只看它有没有做到下面几件事：

- 开始前先读取当前客户资料、上一阶段主文档和最新审核意见。
- 每个 Skill 只负责一类清楚的工作，例如竞品收集、关键词整理、Brief、正文或 QA；上一步的结果直接交给下一步，不重复收集同一批资料。
- 输出时同时留下客户主文档、执行表、来源和交接说明，不能只生成一份看似完成的正文。
- 遇到抓取失败、数据缺失、产品事实不清或路径未确认时，明确停下来并写出缺什么，不能自行补齐。
- 默认套用 AgentGuard 已通过审核的内容结构，但关键词、竞品、页面数量和文章要求必须按当前客户重新查询。
- 飞书写入、CMS Draft 和网站发布分开处理。Skill 不能因为已经生成内容就自动越过审核和发布批准。

如果现有 Skill 已经满足这些要求，就不为“标准化”再拆更多层。只有反复出现同一种返工时，才把解决办法补进对应 Skill 或 QA 清单。

AgentGuard 的版式已经经过多轮审核。新项目默认从这些格式复制空白结构，再填新客户自己的数据和内容。除非客户的网站类型确实不同，否则不要临时发明另一套表头和文档顺序。

## 贯穿全程的五条规则

### 1. 竞品分三种，不要混成一张名单

- 产品竞品：商业上可能被客户拿来比较。
- SEO 竞品：经常在目标关键词的搜索结果里出现。
- 单篇内容竞品：只对当前这篇文章的写法有参考价值。

一个品牌可以同时属于几类，也可能只属于一类。大公司或媒体可以作为页面写法参考，但不能因此写成产品竞品。

### 2. 竞品页面抓不到，不等于它没有内容

先读取公开页面。遇到反爬、登录墙或页面脚本导致正文拿不到时，改用搜索结果快照、浏览器可见页面或其他公开入口补证据，并记录缺了什么。不能把“没抓到”写成“对方没有”。

### 3. 三方数据是估算值，不是客户后台数据

DataForSEO 用来查竞品页面、关键词、搜索量、意图和当前搜索结果。GSC、GA4 用来回答客户自己网站的曝光、点击和转化。两类数据不能互相冒充；工具没返回的数值保留为空，不能写成 0。

### 4. 母库负责规划，当前搜索结果负责单篇生产

关键词和页面母库可以支撑几个月的规划，但真正写某一页前，仍要重新检查当前搜索结果和同类型页面。搜索结果会变，Best、Guide、Compare、Glossary 的写法也不同。

### 5. 审核稿和网站上线是两件事

文档进入飞书或 CMS Draft，只代表客户可以审核。路径、作者、日期、公开图片地址、内部链接、法律口径和最终批准没有齐全前，不能写成“已上线”。

## 怎么判断可以进入下一阶段

进入下一阶段前，至少回答下面几个问题：

- 上一阶段承诺的主文档和表是否已经交付？
- 每个重要结论能否找到来源？
- 缺失数据是否被明确标出，而不是被填成 0 或猜测？
- 客户是否确认了会影响后续工作的事项，例如最终域名、目标市场、产品定位、页面路径和优先级？
- 下一阶段的人是否知道该读哪份主文档，不需要从几十个原始文件里猜结论？

有一项会改变后续方向且还没确认，就停在当前阶段。可以继续整理资料，但不要把未确认内容写进正式页面。

## 新客户启动时的飞书目录

建议直接沿用下面的顺序：

```text
00 项目总览与待确认项
01 站点基线与技术 SEO
02 竞品、页面与关键词母库
03 网站架构与核心页面
04 Blog 模板与首批内容
05 下一批内容规划
06 每周交付与审核记录
```

每个目录先放客户主文档，再放执行表和来源附件。这样客户先看结论，执行人员仍能向下追到数据源。
