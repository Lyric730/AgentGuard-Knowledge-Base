# 第二阶段 SOP：竞品、页面和关键词母库

对应 AgentGuard 周期：2026-07-14 至 2026-07-20

## 这周要解决什么

这是整套服务最重要的资料收集阶段。

目标不是只交一张关键词表，而是建立两份可以反复使用的母库：

1. 竞品页面母库：竞品靠哪些页面获得搜索流量。
2. 关键词母库：这些页面分别通过哪些关键词获得排名。

后面的网站架构、关键词总表、内容规划、竞品页面拆解、Brief 和正文，都从这两份母库往下做。

## 开始前要准备什么

- 第一阶段确认的目标市场、语言、正式域名和产品事实。
- 客户提供的竞品名单。
- 一组能代表客户业务的核心主题，不需要一开始就列几百个词。
- DataForSEO 账号、可用额度和本轮成本上限。
- 允许读取的公开竞品页面范围。

## 一步步怎么做

### 第一步：从全网筛选约 10 个有用的竞品

用核心主题搜索当前结果，同时检查客户给出的竞品和行业内常见品牌。每个候选都要打开官方页面确认它是谁，不能只看品牌名或搜索摘要。

把候选分成三类：

- 产品竞品：客户销售或采购时可能真正遇到的替代方案。
- SEO 竞品：经常在目标主题的搜索结果里出现，值得研究它的流量页面。
- 内容参考站：产品不一定相似，但某类页面做得好，可以学习信息组织和写法。

AgentGuard 当时保留了 9 个主要研究对象。以后默认先找约 10 个，但不要为了凑数留下不相关网站。

### 第二步：先保存竞品的公开页面

读取竞品官网的导航、产品页、解决方案页、文档和内容目录，先形成每个站点的页面清单。

遇到反爬或脚本页面时，按这个顺序处理：

1. 先读取正常公开页面。
2. 再看浏览器里实际可见的内容和站点公开入口。
3. 用当前搜索结果、页面标题和其他公开证据补齐可确认部分。
4. 记录哪些页面没拿到正文，以及原因。

抓不到页面不等于页面不存在。没有正文证据时，不能编写对方的页面结构和产品结论。

### 第三步：用 DataForSEO 拉竞品的主要流量页面

把筛选后的竞品域名交给 DataForSEO。默认先取每个竞品排名靠前的 100 或 200 个页面。

每条至少保留：

- 竞品名称和域名。
- 页面 URL 和标题。
- 主要排名市场和语言。
- 页面排名、流量或关键词数量等工具返回的数据。
- 拉取日期和来源。

网站很小可以少取，网站很大或行业很宽可以增加。调整数量前先看预算和新增页面是否仍然相关。

### 第四步：查询每个页面的 Top 50 关键词

继续用 DataForSEO 查询上一步页面排名靠前的 Top 50 关键词。

每个关键词保留它来自哪个竞品页面，以及工具返回的排名、搜索量、CPC、搜索意图、市场等信息。工具没有返回的值留空，不能填成 0。

这一步很重要，因为同一个关键词单独看时很难判断该做什么页面；知道它现在由哪类竞品页面获得排名，才能判断它更适合产品页、Guide、Best、Compare、Review 还是 Glossary。

### 第五步：合并、去重，但保留来源

把所有竞品页面和关键词合并成母库。大小写、空格和完全重复的关键词可以统一，但每个词原本来自哪些页面要继续保留。

清理明显无关的品牌词、招聘词、其他行业词和无意义组合。不能只靠词面批量删除，边界词要人工看搜索意图和原页面。

### 第六步：逐个判断关键词

为每个保留词补上：

- 搜索者想完成什么。
- 适合哪种页面类型。
- 属于哪个主题。
- 应该现在做、以后做，还是排除。
- 对应现有页面还是新页面。
- 是页面主词还是辅助词。

同一搜索意图只给一个主页面，其他相近词作为辅助词放到同一页，避免多个页面互相竞争。

### 第七步：从母库生成第一批规划

从整理后的数据继续产出：

- 关键词总表和关键词与页面对应表。
- 主题分组和内容集群。
- 网站栏目、URL Map 和新增页面建议。
- 页面优先级和月度内容计划。
- 不同页面类型需要的共用模板。

这些不是五次独立调研。它们都使用同一份竞品页面母库和关键词母库，只是从不同角度整理。

## 这周会得到哪些产出

| 产出 | 怎么来的 | 后面拿来做什么 |
|-|-|-|
| 竞品池与竞品报告 | 全网搜索、客户名单、官方页面核验 | 产品对比、长期跟踪、单篇竞品选择 |
| 竞品页面母库 | DataForSEO 的竞品主要流量页面 + 公开页面清单 | 页面类型统计、网站架构、竞品结构拆解 |
| 关键词母库 | 每个主要竞品页面的 Top 50 关键词 | 关键词总表、聚类、主词与辅助词、优先级 |
| 排除词与待复核清单 | 清洗和人工判断 | 防止无关需求进入正式规划，保留边界问题 |
| 关键词与页面对应表 | 搜索意图 + 竞品页面类型 + 客户现有 URL | 决定改旧页还是建新页 |
| 网站栏目和 URL Map 初稿 | 页面母库 + 关键词分组 + 客户业务 | 第三阶段页面策划 |
| 内容计划和页面优先级 | 搜索机会、业务价值、证据和制作依赖 | 安排先做哪些页面 |

## 同一批资料还能支持什么

- 竞品页面母库可以继续拆网站目录、页面类型、标题、正文结构、视觉和 CTA，不需要再找一批竞品 URL。
- 关键词母库可以按不同角度生成关键词总表、页面执行表、内容日历和内链建议，来源仍然指回原竞品页面。
- 产品竞品名单会给后续 Best、Review 和 Compare 提供候选，但写具体页面前仍要重新核对双方当前资料。
- 排除词和边界词能帮助后续 Agent 理解项目范围，避免下一轮又把无关主题加回来。

## 以后照 AgentGuard 哪份格式交付

客户看到的关键词规划，默认参考：

- `review-pack/task1-p0-client-deliverables/01-keyword-intent-mapping.md`

它把页面、路径、主词、辅助词、搜索意图、页面状态和客户待确认项放在一起。以后新增客户时保持这些栏目，不要只交“关键词 + 搜索量”两列。

关键词总表和页面执行表继续沿用 AgentGuard 飞书里的列结构。可以增加客户特有字段，但不要删掉来源、市场、意图、页面类型、目标 URL、优先级和状态。

## 什么情况下不能进入下一阶段

- 竞品只是客户口头给的名单，没有核验官网和实际相关性。
- 只拿到了域名关键词，没有拿到“页面与关键词”的对应关系。
- 关键词已经去重，但来源页面被删掉，无法再做页面拆解。
- 目标市场混在一起，全球数据和单一国家数据没有区分。
- DataForSEO 没返回的数据被当成 0。
- 关键词还没有经过搜索意图和页面类型判断。

出现这些情况时，关键词表看起来可能很大，但不能直接拿去定网站架构或写 Brief。
